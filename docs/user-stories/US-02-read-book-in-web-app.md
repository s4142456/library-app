# US 02 Read a Book in the Web Application

This narrowed story records elapsed reading-visit time for US 03. It does not measure active attention, persist page history, resume reading progress, or recover abandoned sessions. A session starts after content loads and ends when the server receives a Finish or page-exit update. Sessions without an end time remain incomplete and are excluded from analytics.

## MongoDB Reading Session Shape

```javascript
{
  _id: ObjectId("..."),
  userId: 17,
  bookId: 42,
  startTime: ISODate("2026-10-28T10:00:00Z"),
  endTime: ISODate("2026-10-28T10:45:00Z")
}
```

`endTime` is null until a completion update is received. The domain/API name `sessionId` maps to MongoDB `_id`; it is not a second stored identifier. No stored duration is needed because it is calculated as `endTime - startTime`.

## Suggested Interface Contract

```http
POST  /api/reading-sessions
PATCH /api/reading-sessions/{sessionId}/finish
GET   /api/books/{bookId}/content
```

## Storage Responsibilities

- MySQL is authoritative for users, books, authors, publication state, and protected content references.
- Protected file or object storage, or controlled HTML content, stores the actual readable book content.
- MongoDB stores session identity, user/book references, and start/end timestamps.
- MongoDB `userId` and `bookId` reference MySQL identifiers, but MongoDB cannot enforce those foreign keys.
- The server validates the MySQL user and book before creating a MongoDB session.
- No distributed transaction is required between book metadata and session activity.

## Candidate MongoDB Indexes

```javascript
db.reading_sessions.createIndex({ userId: 1, startTime: -1 })
db.reading_sessions.createIndex({ bookId: 1, startTime: -1 })
db.reading_sessions.createIndex({ endTime: 1 })
```

The final indexes must be justified with actual query and aggregation execution evidence.

## Session Policy

- A new reader visit, including a refresh, creates a new session after readable content loads.
- Retrying the same opening request must not create duplicate sessions.
- Finish Reading and best-effort page-exit updates use the same idempotent completion behavior.
- Browser closure is an intended end of a visit, but its notification is not guaranteed to reach the server.
- An unreceived completion update leaves endTime null; the session is excluded from analytics.
- Duration measures elapsed visit time, including idle time within the visit. It does not measure verified active reading.
